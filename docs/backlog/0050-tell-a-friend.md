## User story

As a user who has a composed plan and a friend who is always tired and always told "everything's normal" — but who does not want to write a paragraph explaining what Almanac is — I want a one-tap "Share with a friend" on the Plan page that pre-composes an honest, plain-text recommendation in my own situation's terms (the top thing I am actually doing, the marker that has moved if one has, and a link to the sample tour the friend can tap with no commitment), so that recommending the product is one tap of the native share sheet instead of a writing task — and the friend gets a real, personal, no-pressure introduction that I did not have to compose.

## Why now (four lenses)

### Product Owner

The product already has every artifact channel except the most natural one: the spoken recommendation. The share link (0017, shipped) sends the *live, tappable protocol* to a specific person; the improvement card (0047, groomed) and the protocol card (0033, groomed) render *images* a user posts or texts; the sample tour (0014, shipped) and sandbox (0040, shipped) are where a curious friend lands. What is missing is the bridge a user uses a dozen times a day in every other app: the native share sheet, pre-filled with a message they would actually send. Today, recommending Almanac is a writing task — the user has to explain what it is, find the link, and compose a sentence — and a writing task at the moment of casual enthusiasm is exactly where a recommendation dies. The smallest meaningful unit of value is a "Share with a friend" affordance on the Plan page that assembles a pure-ASCII, pre-written recommendation from data already on the device: the user's top eat-list item (the first food, with its frequency), their most-improved marker if one exists (reusing `selectMostImproved` from 0047 verbatim — the same honest selection that powers the improvement card), the wordmark, and the canonical sample-tour path (`#/try`). On a phone it opens `navigator.share()` (the OS share sheet — Messages, WhatsApp, wherever); on desktop, where `navigator.share` is absent or blocked, it falls back to clipboard copy with a transient "Copied." It is a zero-network, zero-key, zero-backend assembly of a sentence the user can send in one tap.

### Stakeholder

This is the **structured artifact** and **persistent timeline** moats turned into the product's missing peer-recommendation channel — the one that needs no backend, no link shortener, no tracking, and no analytics to function. It compounds 0047 directly: `selectMostImproved` is the honest, dual-range, canonicalized selection that already makes the improvement card trustworthy; reusing it here means the shared text's "my ferritin went 32 → 48" claim is true by construction (a real move toward a real functional optimum, on the user's own dated draws) and is omitted gracefully when no such move exists — the recommendation never overclaims. It compounds 0014/0040: the shared message lands the friend in the already-built pre-key funnel (the tour and sandbox), where conviction is formed on the friend's own terms. And it is a structural advantage the chat box cannot match: raw Claude has no top-eat-item, no most-improved marker, and no shareable artifact — "here is a pre-written, honest recommendation built from my actual protocol" is a sentence only a product with persistent, structured, on-device state can compose. Crucially it stays inside the privacy contract: the share payload is assembled entirely on-device from the current plan and the improvement selection, carries no http/https or tracking parameter except the canonical tour path, and makes zero network calls — the user's biology never travels; only a single food, a single optional marker delta, the wordmark, and the public tour link do.

### User (at 7am on the phone)

I just composed my plan, and the friend who is always exhausted and always "fine" on her labs comes to mind. On the Plan page, beside the other actions, "Share with a friend." I tap it. The OS share sheet comes up with a message already written, in plain words I would actually use: "I've been using Almanac to turn my labs into a daily protocol. Right now I'm eating fatty fish 3x per week, and my ferritin came up from 32 to 48 — finally in range. If you've ever been told 'everything's normal' but didn't feel it, try it with your own numbers: [tour link]." I pick Messages, pick her, send. I did not have to explain anything or write a word — the honest version of what I would have said was already there. If my labs had not moved yet, the message just leaves out the marker line and still reads true. On my laptop the same button copies the same text and says "Copied." It worked offline, instantly, because the message is built from my own plan already on the device — no call, no wait, no key.

### Growth

This is the highest-frequency acquisition channel the product can build, because it rides the one gesture users already make reflexively — the native share — at the moment of genuine enthusiasm (a freshly composed plan). (Hypothesis: a pre-composed, one-tap peer recommendation converts at a meaningfully higher rate than the share link 0017 or the image cards, because it removes the writing tax that suppresses casual recommendations — the dominant friction on word-of-mouth is not willingness but effort, and a pre-written honest message collapses that effort to one tap; and the message lands the friend in the shipped pre-key funnel, so the channel is the top of an existing conversion path; back-of-envelope from how one-tap share-with-prefilled-text outperforms copy-a-link in referral flows; treat as untested without remote analytics, which we will never add.) The "show me" frame is the message itself: an honest, specific, no-hype recommendation in the user's own situation's terms — "I'm eating fatty fish 3x a week and my ferritin came up" — is exactly the line the persona uses on the one friend with the same complaint, and this makes sending it one tap instead of a paragraph. It is the peer-channel sibling of the practitioner channel (the coach packet 0048): same no-backend, wordmark-carries-the-brand, honest-by-construction mechanic, aimed at the friend whose word the prospect trusts most.

## Acceptance criteria

The wordmark "Almanac" appears in the text. Pure: no DOM, no Dexie, no network, no clipboard, no `navigator.share`. - [ ] The marker claim appears ONLY when `selectMostImproved(...)` (reused verbatim from 0047's `src/progress/most-improved.ts` — no second implementation) returns non-null. When it returns null, the composed message omits the marker line entirely and still reads as a complete, grammatical recommendation. Asserted by composing once with a non-null improved (marker line present) and once with null (marker line absent, message still coherent).
- [ ] The composed string is pure ASCII and contains NO `http`/`https` substring and NO tracking parameter (no `?`, no `utm`, no query string) — the ONLY link-like token is the canonical tour path `#/try`. There is no image, no QR code, no shortlink, no URL to any host. - [ ] The Plan page (`src/pages/plan.ts`) renders a "Share with a friend" affordance near the existing plan actions, present ONLY when a composed plan exists. - [ ] The share is performed with **zero network calls** and **zero Anthropic calls** — the message is a pure transform of the local plan + the local improvement selection; the share sheet and clipboard are device-local. Asserted by tapping the action (both share and clipboard branches) and confirming the mock recorded zero requests.
- [ ] The Anthropic key NEVER appears in the composed message or any intermediate string. Asserted by seeding a sentinel key on the profile and confirming the sentinel appears nowhere in the composed text or the share/clipboard payload.
- [ ] Marker names in the marker line resolve to human names via `findMarker()` (inherited from 0047's `selectMostImproved` resolution), including sex-specific keys ("Ferritin", not `ferritin_m`) and user-defined markers (0002). - [ ] The composed copy honors the voice spec: no banned words ("journey", "amazing", "exciting", "great"), no emoji, no exclamation marks; the recommendation is stated plainly, not as a boast. Asserted by a content assertion that the composed text contains none of the banned tokens.

## Out of scope

Explicit anti-goals. The dev agent will not do these even if they seem related.

- A backend link shortener, a per-share tracking URL, or any UTM/referral parameter. We have no backend and no analytics; the only link in the message is the canonical `#/try` fragment, which carries nothing personal and is the same for everyone. Adding a tracking parameter would both widen the (nonexistent) backend surface and violate the no-analytics contract.
- An image, QR code, or rich attachment in the share. The artifact is plain ASCII text — maximally portable, paste-clean into any messenger, and incapable of carrying a hidden tracker. The image-share artifacts already exist (the improvement card 0047, the protocol card 0033); this is the text-recommendation channel, deliberately distinct.
- Sharing the user's live protocol (eat list, avoid list, habits) in the message. That is the share link's job (0017), which sends the full tappable protocol. This message is a *recommendation* — a single top action and an optional marker delta — sized to be a sentence a person actually sends, not a data dump.
- An LLM-generated recommendation. The message is a deterministic assembly of the top eat item + the most-improved marker; a Claude call would add cost, latency, non-determinism, and an egress to a feature whose value is being instant, local, and provably honest. The user's own data writes the sentence.
- Composing the message from anything other than the current plan + `selectMostImproved`. No re-deriving the improvement here — reuse 0047's function verbatim so the claim is identical to the improvement card's and honest by construction.
- A "share to a specific platform" button set (Share to WhatsApp, Share to X, etc.). `navigator.share` hands off to the OS sheet, which already lists every installed target; per-platform buttons add surface and break the one-tap promise. Desktop falls back to clipboard, which pastes anywhere.
- Carrying the share message into the doctor PDF (0010/0016), the Markdown export (0027), or any stored artifact. It is an ephemeral, on-demand recommendation, not part of the record.

## Engineering notes

Files / patterns the dev should touch. Be specific enough that the dev doesn't have to re-discover the architecture.

- `src/plan/share-message.ts` (new) — `composeShareMessage(plan, profile, improved)`. Assemble the ASCII recommendation per the acceptance bullets. Read the top eat item from `plan.eatList[0]` (guard the empty case — if a plan has no eat list, omit the food line but keep the rest). The marker line is built only when `improved` is non-null, using `improved.name`, `improved.startValue`, `improved.nowValue`, `improved.unit`, and `improved.movedIntoRange`. The canonical tour path is the literal `#/try` (the route 0040 registered). Pure string assembly; no I/O.
- `src/progress/most-improved.ts` (0047) — read-only consumer. Reuse `selectMostImproved(panels, profile)` verbatim to get the optional improvement; do NOT re-implement the selection. The Plan page passes `allPanels()` + profile into `selectMostImproved`, then passes the result into `composeShareMessage`.
- `src/pages/plan.ts` — add the "Share with a friend" affordance in the plan-actions region (where the share link 0017 and any card-save 0033 actions live), gated on a composed plan existing. Wire it to compute the message and call `navigator.share({ text })` when `typeof navigator.share === "function"`, catching a rejection/throw and falling back to `navigator.clipboard.writeText(text)` + a transient "Copied." Reuse the existing transient-confirmation idiom (the share-link / share-card flows already have one). Do not invent a second share or download mechanism.
- `src/data/markers.ts` — read-only. `findMarker()` resolves the human marker name (inherited via `selectMostImproved`).
- `src/types.ts` — no new persistent types; any internal type lives in `share-message.ts`.
- `src/styles.css` — one new action styled like the existing plan-page actions (the 0017 share-link action is the closest sibling); ≥44×44 css px (min-height ≥45 px per the sub-pixel lesson). No new colors; ink and ink-soft, oxblood reserved.
- `src/share/shared-state.ts` / `src/sample/state.ts` — gate with `isSharedView()` (absent — the recipient has no own-plan/own-improvement) and `isTour()` (present against the fixture plan).
- `tests/helpers/flows.ts` — reuse `composePlan` (and `seedPanel` from the 0026/0032/0047 specs) to seed a plan plus two dated panels with a favorable move so `selectMostImproved` is non-null in one test and to seed a plan with a single panel so it is null in another. Stub `navigator.share` via `page.addInitScript` to test the present branch and capture its argument; assert the clipboard via Playwright's clipboard permission for the fallback branch.
- `tests/e2e/tell-a-friend.spec.ts` (new) — every acceptance bullet maps to a `test()`. The marker-line test composes once with a non-null improved and once with null. The no-tracking test asserts the composed string contains `#/try` and matches the pure-ASCII regex with no `http`/`?`/`utm`.
- `tests/e2e/privacy.spec.ts` — extend with a share invocation (both branches) confirming zero off-allow-list egress and that the key never appears.
- New deps: **no** — `navigator.share` and `navigator.clipboard` are platform APIs; the message is string assembly.
- Egress allow-list change: **no**.
- Schema migration: **no**.
- Voice spec: the message reads "I've been using Almanac to turn my labs into a daily protocol. Right now I'm eating <food> <frequency>." then, when present, "My <marker> moved from <start> to <now> <unit> — now in range." then "If you've ever been told everything's normal but didn't feel it, try it with your own numbers: #/try" The on-screen fallback confirmation is "Copied." Declarative, no exclamation, no boast. Banned: "amazing," "exciting," "journey," "great." The wordmark is "Almanac"; the only link is `#/try`.
