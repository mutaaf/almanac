## User story

As a user who just composed my first plan and is about to close the tab, I want a calm, dismissible note telling me — once — that I can install Almanac to my home screen so the protocol opens with one tap the way Messages and Calendar do, with the exact instructions for my browser ("Tap the share icon, then 'Add to Home Screen'"), so that tomorrow morning I can actually find the app instead of digging through a thicket of tabs and forgetting it was there, and the second day's protocol is one icon away instead of one URL-search-and-bookmark-hunt away.

## Why now (four lenses)

### Product Owner

The single biggest cause of a freshly-converted user never returning is structural, not motivational: the web app lives in a tab, the tab gets closed, and the user has nothing on their home screen to remind them tomorrow morning that they have a daily protocol to open. The product has built every piece of retention infrastructure — the daily check-in, the streak strip, the meals, the habit stack, the lapse-aware welcome-back (0018), the retest countdown (0028), the catch-up grid (0058) — and all of it is gated on the user remembering to open the URL. There is no manifest, no service worker, no add-to-home-screen affordance, no PWA infrastructure in the bundle at all today. The smallest meaningful unit of value is twofold and tightly bounded: (1) ship a minimal `manifest.webmanifest` (name, short name, theme + background color from the ink/cream palette, an icon set, `display: standalone`, `start_url: "/#/today"`) so the OS recognizes the app as installable; (2) on Today, the FIRST time a user lands there after a real plan has been composed, render once a calm, one-paragraph "Put Almanac on your home screen" primer with browser-specific install instructions (Safari iOS: "Tap the share icon, then 'Add to Home Screen.'" Chrome Android: "Tap the menu, then 'Install app' or 'Add to Home screen.'" Desktop: "In your browser's address bar, tap the install icon."), a "Dismiss" affordance, and nothing else — no shadow nag, no auto-popup, no `beforeinstallprompt` interruption. Dismissed once, it never returns. No service worker, no offline shell beyond what the bundle already supports, no push, no telemetry of installs (we have no analytics). It collapses "remember to find this app tomorrow" from a URL hunt into one tap on a home-screen icon.

### Stakeholder

This widens the **timeline-density** moat at its most structurally vulnerable seam: a daily-protocol product whose entire compounding mechanic — adherence, streaks, meals, the retest loop — depends on the user opening it every day, while living in a browser tab is the worst possible distribution shape for daily opening. The chat-box comparison is structurally won here: Claude.app is a place the user goes when they have a question; an installed PWA is a place the user opens because it sits between Messages and Calendar on a home screen. No backend is added; no analytics; no widening of the egress allow-list (the icons ship in the bundle, the manifest is a static file). And the discipline is exactly what AGENTS.md asks for: a local primitive (a static manifest + a one-time copy block on Today) doing a job a backend product would do with a push notification. The install moment is the conversion close from "I tried this app once" to "this is the app I open in the morning," and the product has all the daily-value already built — it just has no current way to ask the user to make daily-opening physically convenient. A user with the icon on the home screen is dramatically more likely to be there a week, a month, and three months in — which is the precondition for every retest, every plan recomposition, and every improvement card the moat depends on.

### User (at 7am on the phone)

I composed my plan last night, closed my laptop, and now it is the morning. On Today, above the meals, a single calm paragraph in the editorial type: "Put Almanac on your home screen — so it opens like Messages." Below it, three short lines for the browser I am actually on: "Safari: tap the share icon, then 'Add to Home Screen.' Chrome Android: tap the menu, then 'Install app.' Desktop: tap the install icon in the address bar." A "Dismiss" link beside it. I follow the three taps, the icon lands on my second page beside Calendar, and tomorrow morning I open the protocol the same way I open Messages — without thinking, without finding a URL, without remembering which browser tab I was last in. If I tap "Dismiss" instead, the card never comes back. If I install it, the card never comes back. It is the kind of small thing every other competent web app has on day one; the only reason we have not had it is that we never wrote the manifest.

### Growth

This is the highest-leverage retention surface the product can build in 2026, because it converts a one-time visitor into a daily user via the only durable distribution channel a no-backend product has: the home screen. (Hypothesis: installing a PWA to the home screen is the single biggest predictor of week-2 and month-1 return rates in daily-use web apps, because it removes the URL-hunt that suppresses daily opening; offering it once at the post-compose moment — the highest-conviction point in the funnel — converts at materially higher rates than offering it on welcome or burying it in settings; back-of-envelope from how PWA install rates correlate with retention in habit-tracking and journaling apps; treat as untested without remote analytics, which we will never add.) The acquisition compounds too — a user with the icon on their home screen is the user who shows the friend at coffee "look, this is what I open every morning," which is the most credible recommendation surface the product has: the visible, daily-used app, not a link. The "show me" frame is the home screen itself — the icon between Calendar and Notes — which carries the wordmark and the editorial palette into a place a friend physically sees. It is the daily-opening sibling of the protocol-card (0033, shipped): 0033 puts a screenshot of today's protocol on a fridge; this puts the live app on a phone in the same gesture every other daily tool gets.

## Out of scope

Explicit anti-goals. The dev agent will not do these even if they seem related.

- A service worker, an offline shell beyond what the Vite bundle already supports, or any background-sync mechanism. The PWA install primer is about getting the app on the home screen so the user opens it; it is not about making the app work offline (the IndexedDB-first architecture already handles the persistence question). A service worker is a separate, larger design with its own caching and update concerns.
- A web-push notification, badge, or any kind of nag. AGENTS.md forbids the server-side push, and the README's no-pressure posture forbids the foreground nag. The primer is one calm paragraph, dismissed once, gone forever. No "still not installed?" follow-up. No "tap to install" auto-prompt via `beforeinstallprompt` event.
- Tracking or counting installs. There are no analytics in the product (AGENTS.md non-negotiable); whether a user installed is not measured, not stored, not surfaced. The dismissal flag is private localStorage state for primer suppression only.
- An `apple-mobile-web-app-status-bar-style: black-translucent` or anything that changes the visual chrome beyond the documented theme color. The status-bar style is the safe default that matches the cream background.
- A multi-step install wizard, an animated arrow pointing at the share icon, or an embedded video. The primer is plain editorial copy with three short instruction lines — same voice as every other Today surface.
- Carrying the primer onto the welcome screen pre-consent. The primer requires a composed plan (the user has earned the suggestion); putting it pre-consent would be a pitch before substance, which the product's posture forbids. (A pre-consent install affordance is a clean follow-up only if the welcome conversion rate genuinely demands it.)
- Adding a deep-link to a native app, an iOS App Store badge, or any platform-specific store referral. There is no native app; the PWA install IS the install.
- A "Reinstall" / "Re-show the primer" affordance in settings. The dismissal is permanent within a browser; if a user wants to reinstall, they use their browser's native install affordance (the address-bar icon on desktop, the share-sheet on iOS).
- Auto-detecting the user's browser and showing only the matching instruction line. v1 shows all three; the user picks the one that matches what they see. Auto-detection is brittle (especially on iOS in-app browsers) and a wrong detection is worse than the small noise of three lines.

## Engineering notes

Files / patterns the dev should touch. Be specific enough that the dev doesn't have to re-discover the architecture.

- `public/manifest.webmanifest` (new, or wherever Vite expects static assets — confirm against `vite.config.ts` and document the chosen path) — the JSON manifest with the documented fields. Use the existing palette: `background_color: "#fbf6e9"` (cream) and `theme_color` ink (the existing token; pull from `src/styles.css` so the value stays in sync). `start_url: "/#/today"` so the installed app opens directly into the daily protocol surface, NOT the welcome screen — by the time the user installs they have already consented.
- `public/icon-192.png` and `public/icon-512.png` (new) — flat PNG icons rendering the wordmark "Almanac" in Cormorant Garamond display, ink on cream, with appropriate padding. Generated once and committed to `public/`; not generated at build time (no new dep). If the team wants `maskable` icons, add one of each size with the proper safe area; if not, the regular icons are sufficient for v1.
- `index.html` — add `<link rel="manifest" href="/manifest.webmanifest">`, the `<meta name="theme-color">` matching the manifest, the apple-touch-icon link, and the apple-mobile-web-app-* metas. Place them in the existing `<head>` in editorial order with the other metas.
- `src/today/install-primer.ts` (new) — `shouldShowInstallPrimer({ hasComposedPlan, dismissedAt, isStandalone })` (pure boolean). Also export a tiny helper `isStandalone()` that wraps the `matchMedia` + `navigator.standalone` detection so the page does not duplicate the logic.
- `src/pages/today.ts` — read `latestPlan()` (the page already does this for the meals/habits), read `localStorage.getItem("almanac.installPrimer.dismissedAt")`, compute `isStandalone()`, call `shouldShowInstallPrimer(...)`, and render the primer at the documented slot when true. Wire the "Dismiss" affordance to write `localStorage.setItem("almanac.installPrimer.dismissedAt", new Date().toISOString())` and re-render Today (or remove the primer DOM node in place). Do NOT block the Today render on the primer — it is a non-critical layer.
- `src/styles.css` — `.install-primer` (the section) and `.install-primer__instructions` (the three browser-specific lines), reusing the existing editorial section / quiet-day card idioms. Ink/ink-soft, no oxblood, no card shadow — it sits among the other Today layers calmly. The "Dismiss" link is a `box-sizing: border-box; min-height: 45px` button-styled link (per the 0017 LESSON). Grid children `min-width: 0`.
- `src/sample/state.ts` / `src/share/shared-state.ts` — gate the primer with `!isTour() && !isSharedView()` (the primer is owner-only).
- `src/chrome.ts` — no change; the masthead does not carry the primer.
- `tests/helpers/flows.ts` — add a small helper to set/clear the `almanac.installPrimer.dismissedAt` localStorage key from the spec; reuse `acknowledgeConsent` + `onboard` + `composePlan` for the post-compose state.
- `tests/e2e/install-primer.spec.ts` (new) — every acceptance bullet maps to a `test()`. The manifest test fetches `/manifest.webmanifest` and parses the JSON. The standalone-suppression test stubs `matchMedia("(display-mode: standalone)")` to return `matches: true` via `page.addInitScript` and confirms the primer is absent. The browser-instructions test confirms all three lines appear verbatim regardless of the test's user-agent.
- `tests/e2e/privacy.spec.ts` — extend with a Today visit that loads the manifest + icons and dismisses the primer, confirming the only fetched hosts are the same-origin shell + the allow-listed Google Fonts. The manifest and icons are same-origin, so no new hostnames are introduced.
- New deps: **no**. The manifest is a static JSON file, the icons are static PNGs, the meta tags are HTML, the dismissal flag is localStorage — every primitive is platform-native.
- Egress allow-list change: **no** — the manifest, icons, and meta tags are all same-origin; the privacy spec's allow-list (`127.0.0.1, localhost, fonts.googleapis.com, fonts.gstatic.com, api.anthropic.com`) is unchanged.
- Schema migration: **no** — the dismissal lives in localStorage, not IndexedDB.
- Voice spec: the primer eyebrow reads "Put Almanac on your home screen"; the body opens "So it opens like Messages — one tap, no URL." The three instruction lines read as documented above. The "Dismiss" link reads "Dismiss." Declarative, no exclamation, no nag. Banned: "amazing," "exciting," "journey," "great." Ink and ink-soft only.
